# Craft applications in WebPC

These are the official Storytold browser applications, not replacement editors. WebPC loads each app only when its window opens. The Rust/WASM editors, native tools, fonts, workers and file formats come from their release archives.

GridCraft and DeckCraft take over the grid and presentation roles WebPC's former Sheets and Slides apps had; those apps were removed. CasualOffice Docs stays as its own app, outside the Craft pipeline.

VectorCraft, PhotoCraft, EffectCraft, MaterialCraft and TextureCraft run in **standalone mode**: their pinned web builds ship no `?host=parent` ready/open/save bridge (`craft-web-host` is absent from their web crates), so the wrapper loads them at `?webgl&standalone` instead of inventing a protocol. On load it hands the iframe three facts from `releases.mjs`: the native document pattern, the app's own documented open method (if any) and its loading element. Readiness is a generic poll (editor canvas present and the app's own loading element gone). Wrapper **Open file** uses the app's real open path: `window.vectorcraft.openFile(name, bytes)` (its documented control channel), `window.effectcraft.addFile(file, name)` (its documented agent API), and a synthetic file **drop** for the other three (PhotoCraft reads a drop off the document canvas — on the tab bar — as an open, the other two open any dropped document). Native downloads stay intact; a download named after the document's own format is also copied to the wrapper's browser-save handler. Since these builds expose no dirty bridge, leaving a ready standalone window gets a conservative browser confirmation; a cached WebPC window closes without prompting after the editor is suspended.

PhotoCraft's 0.23.1 archive has a packaging gap: it ships its eframe snippet only at root `snippets/`, while `app/photocraft-web.js` imports it from `app/snippets/`, so a stock bundle 404s and stays in its loader. `prepare-craft.mjs` therefore copies `snippets/` to `app/snippets/` for photocraft only, throws if neither location exists, and skips the copy once a future release ships `app/snippets/` itself.

## Prepare and update

Run `npm ci` and `node scripts/pc/prepare-craft.mjs`, or use the normal `npm run dev` / `npm run build` pipeline. Preparation needs Node, network on first use, and `unzip`. No Rust build, private checkout, sibling repository or absolute browser path is needed.

`scripts/pc/craft/releases.mjs` pins the release versions, official GitHub URLs and SHA-256 digests. ZIPs cache under ignored `node_modules/.cache/webpc/craft/`. Each ZIP is verified before extraction; unsafe archive paths are rejected. Staging finishes before replacing generated `public/pc/vendor/{app}/`. The marker includes the checksum and integration fingerprint. Update the pins only after reviewing the matching source tag, storage/host contracts, licenses and browser regressions.

The archive's JS/WASM/assets remain unchanged. We add `webpc-bootstrap.js` before startup and an identifying HTML attribute. Unused `.gz`/`.br` siblings and hosting-specific header templates are omitted; ordinary static hosting serves the original files. Full upstream Apache/MIT notices, font licenses, SoundCraft attribution and PDF OCR model attribution/license texts are retained in the release and copied to `public/third-party/{app}/`. PDF OCR models have their own CC-BY-SA-4.0 license; they are unmodified.

## Files and storage

LightCraft uses its native browser library and automatic writes. It starts with upstream's clearly synthetic example photos; imported originals and edits are real library data. Use File → Back Up Library / Restore Library for portable ZIP backups. Image export is a normal download. Its web release cannot implement every desktop preset/curve file dialog.

**LightCraft storage isolation is enforced, including direct vendor URLs.** Its v0.21.1 `apps/lightcraft-web/src/backend.rs` opens the origin OPFS root by default, and `clear()` recursively deletes root entries. The entry script therefore always forces upstream's `store=idb` before initialization. That exact release uses database `lightcraft`, object store `files`; `workers.rs` propagates the selected backend to render workers. Its reset only clears that object store. Do not remove this guard or use default OPFS on WebPC's shared origin.

FigCraft stores its name and crash recovery under `figcraft.userName` and `figcraft.recovery`. PDFCraft stores preferences under `pdfcraft` (reads legacy `printcraft`); these are not document autosaves. SoundCraft has no persistent session or host bridge in v0.20.1. CADCraft keeps its profile, preferences and panel layout under localStorage keys `cadcraft.profile`, `cadcraft.prefs` and `cadcraft.panel-layout` and writes nothing else to browser storage. GridCraft stores its UI and preferences under localStorage keys `gridcraft.ui` and `gridcraft.prefs`; its extracted WASM shows no OPFS or IndexedDB use. DeckCraft persists nothing in v0.18.1: its web entry states that preferences are not persisted, and its extracted WASM contains no storage keys of its own. None of their reviewed web source resets the origin's storage.

VectorCraft keeps its preferences in localStorage and its saved files in wasm memory (up to 16 entries); its extracted bundle shows no IndexedDB or OPFS use. PhotoCraft persists its preset libraries in IndexedDB database `photocraft.presets` and nothing else; the wrapper's drop-open and save-copy paths do not touch that database. EffectCraft keeps its own session, file table and media in OPFS under the `effectcraft/` directory, with an IndexedDB fallback (database `effectcraft`, object store `entries`) when OPFS is unavailable, and a service worker that caches only its own versioned cache (`effectcraft-<version>`); the wrapper loads it with upstream's documented `?nosw` so the injected page script can never be served stale from that cache, and its service worker's only `caches.delete` call drops old `effectcraft-` caches. MaterialCraft and TextureCraft persist only localStorage preferences; their extracted bundles show no IndexedDB or OPFS use.

FilmCraft writes its crash-recovery journal into OPFS (`recovery/snapshot.fcproj`, `recovery/meta.json`) and copies imported media to `media/<name>` (up to 4 GiB per file); its reviewed web source removes only its own OPFS entries and never resets the origin's storage. Its host saves carry a `saveAs` flag: project Saves (and the first Save of a new project) are the document, everything else (exports, captions, AAF/OMF/EDL interchange, extracted audio) is a copy. The wrapper ignores the flag, downloads every save, and only a `.fcproj` replaces the recovery copy. CADCraft marks every host save with `saveAs: false`; the wrapper downloads them all and keeps a `.dxf` or `.dwg` (its two selectable save formats) as the recovery copy, never an SVG or other export. GridCraft marks every host save with `saveAs: false` (Save, Save As and PDF export all download; only the `.xlsx` workbook becomes the recovery copy). DeckCraft says `saveAs: false` for a plain Save (which writes the opened file in its own format, so a `.pptx` stays a `.pptx`) and for every export (PDF, pictures, outline, GIF, handouts); a Save of an untitled deck and every Save As send `saveAs: true` named `<title>.deckcraft` or the chosen `.pptx`/`.deckcraft`, so the wrapper keeps whichever presentation file is saved last.

The wrapper keeps one last **explicitly saved** document/session per app in its separate IndexedDB database `webpc-craft-saves-v1`, object store `files`: `.figcraft`/JSON, PDF, `.fcproj`, `.dxf`/`.dwg`, `.xlsx`, `.deckcraft`/`.pptx`/`.potx`/`.ppsx`, `.scraftz`, `.vectorcraft`, `.pcraft`, `.ecproj`, `.sbs`/`.mcraft`/`*_sbs.zip` (MaterialCraft's web save downloads the package as a transport ZIP) or `.tcraft`. Exports to unrelated formats never replace that recovery copy. Reopen saved is explicit. Changes since Save are not autosaved, and this is not a cloud backup. Native Save always triggers a real download, even when keeping its browser copy fails. Storage errors remain visible; the current bytes can be downloaded again or retried. Corrupt/invalid incoming files remain subject to native validation.

## Host and audio contracts

LightCraft, FigCraft, PDFCraft, FilmCraft, CADCraft, GridCraft and DeckCraft use their actual same-origin `?host=parent` ready/dirty/open/save messages. Listeners are installed before assigning iframe `src`. Every received message checks both `event.origin` and the exact editor window. `?control` enables upstream's documented command API for native browser regression tests. `?webgl` chooses the supported WebGL2 renderer without requiring WebGPU or cross-origin isolation headers.

SoundCraft starts empty (`?empty`), with audio suspended. Its upstream release already wraps AudioContext to resume on gestures; our earlier wrapper gates that resume and immediately suspends newly created contexts until **Enable audio**. Closing the WebPC window suspends all live contexts and requires explicit re-enabling on reopen. The shell keeps the same iframe/session cached. Reload requires a saved `.scraftz` bundle; a plain `.scraft` may not include media. No microphone permission is requested automatically, and the wrapper does not provide desktop plug-ins or recording input.

SoundCraft's native audio/MIDI/session import is driven through its actual file-drop path. Native session replacement calls `open_session_bytes`, which prompts before discarding dirty work. Its native download remains intact; a copy of `.scraftz` downloads goes to the wrapper's browser-save handler. Since this release has no dirty bridge, leaving/reloading an initialized SoundCraft page gets a conservative browser confirmation. Closing a cached WebPC window is allowed after suspending audio.

## Validation and limits

After building, run `npm run test:browser -- tests/browser/pc-craft.spec.mjs`. Tests use the installed Playwright Chromium with software WebGL, real native editors and file bytes. Coverage includes LightCraft import/edit/PNG export/ZIP backup/reload and reset isolation; FigCraft shapes, native save, recovery and quota failure; actual PDF text export/reopen; and SoundCraft nonzero audio output, media bundle export/reimport and audio suspension. The standalone apps (VectorCraft, PhotoCraft, EffectCraft, MaterialCraft, TextureCraft) are covered for ready, their documented open path (command API or file drop) and, for EffectCraft, audio suspension on window close. Storage sentinels cover unrelated localStorage, another IndexedDB database and an OPFS root file.

These large canvas apps work best in maximized desktop windows. The wrapper fits small windows, but no touch-first redesign or full accessibility audit is claimed. Browser/GPU limits and large document memory use still apply. Online sharing or remote collaboration requires a separately configured compatible server; WebPC configures none. Optional native network features are user initiated. Keep important exports outside browser storage.
