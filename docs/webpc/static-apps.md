# Static web apps in WebPC

Prebuilt single-page web apps, integrated unmodified (or with a documented per-app tweak) into WebPC as same-origin iframes under `/pc/apps/<id>/`. Unlike the Craft apps, these are ordinary static bundles: no WASM toolchains, no entry-script bootstrap, no host message bridge.

| App | Release | Route | Runtime assets (raw) |
| --- | --- | --- | --- |
| [SQLiteViz](https://github.com/lana-k/sqliteviz/releases/tag/0.32.1) | 0.32.1 | `/pc/apps/sqliteviz/` | about 4 MB |
| [BeepBox](https://github.com/johnnesky/beepbox/releases/tag/v4.2.2) | 4.2.2 | `/pc/apps/beepbox/` | about 1.3 MB |

## Prepare and update

Run `node scripts/pc/prepare-static-apps.mjs` (also wired into `assets:pc`). The script is table-driven: each row in `staticApps` pins `id`, `version`, `url`, `upstream`, `sha256`, a `notice` (the WEBPC.txt body), and optional `tweak`/`inject`/`license` fields.

For each row: the ZIP caches under ignored `node_modules/.cache/webpc/static/<id>-<version>.zip`; the digest is verified before extraction; unsafe archive paths (absolute, backslash, `..`) are rejected (exported as `isUnsafeArchivePath`, unit-tested in `tests/pc-static-apps.test.mjs`). The ZIP is extracted to a staging folder, the payload (single top-level directory — `__MACOSX` junk aside — or the zip root) is swapped into `public/pc/vendor/<id>/`, and a `.release.json` marker (version + sha256 + url + **fingerprint**) makes the run idempotent. The fingerprint is `sha256` of the preparer's own source plus the row's injected file(s) (exported as the pure `rowFingerprint`, unit-tested), so any preparer or tweak change forces a re-preparation on the next run. `LICENSE`/`NOTICE` files are copied to `public/third-party/<id>/`; rows whose release ZIP ships no licence file pin the repo's licence file by URL + SHA-256 (`license` field). A `WEBPC.txt` states version, upstream URL, release URL, SHA-256 and what WebPC changed. Each string replacement in a tweak fails loudly if the expected upstream string is gone, and tweaked JS is syntax-checked with `node:vm` before it can be served.

## SQLiteViz 0.32.1 (Apache-2.0)

SQL queries and charts over SQLite/CSV/JSON/NDJSON files, fully client-side (sql.js WASM).

- **Bundle**: official Vite `dist.zip`, files at the zip root (no wrapper directory). All asset URLs are relative (`./assets/...`), so it serves from the `/pc/vendor/sqliteviz/index.html` sub-path with **no changes** — no per-app tweak was needed.
- **Routing**: vue-router hash history (`index.html#/workspace`, `#/inquiries`, `#/load`). The iframe src therefore points at the explicit `index.html` file (the dev server does not directory-index `public/` vendor folders).
- **Service worker**: the bundle ships a Workbox service worker (`service-worker.js` + `workbox-*.js`) registered at scope `/pc/vendor/sqliteviz/`. It precaches only its own assets and shows a "new version available" prompt on real updates. Left in place, unmodified.
- **Storage**: `localStorage` keys `myQueries` (saved queries) and `myInquiries` (versioned inquiries object); Vue-DevTools plugin settings under `__vue-devtools-plugin-settings__*` only when devtools are active; the cache API name `mapbox-tiles` is deleted only to evict its own map-tile cache. No IndexedDB, no `localStorage.clear`/`indexedDB.deleteDatabase`/`navigator.storage.getDirectory`. It opens files via `showOpenFilePicker` (user-initiated) and reads its bundled `inquiries.json` via a same-origin `fetch("./inquiries.json")`. **No origin-wide wipe; no scoping needed.**
- **Network**: initial load makes zero non-site requests (verified headless: 42 requests, all `localhost:4322`). No analytics, telemetry, update checks or CDN assets are bundled. The map chart view can fetch tiles and fonts from public map tile servers (OSM/MapLibre basemaps, `fonts.openmaptiles.org`, ArcGIS, ICGC) when the user creates a map — user-initiated data fetching, analogous to CyberChef's URL-fetch operations; noted on the app page.
- **Licence**: Apache-2.0; the bundle's `LICENSE` is copied to `public/third-party/sqliteviz/` with `WEBPC.txt`.

## BeepBox 4.2.2 (MIT)

Chip-tune tracker/DAW: the song is entirely contained in the URL `#hash`.

- **Bundle**: official `BeepBox_4_2_2.zip` (payload dir `BeepBox_4_2_2/`, `index.html` entry, relative asset URLs — serves from the sub-path unmodified). The release ZIP ships no licence file, so the repo `LICENSE.md` at tag `v4.2.2` is pinned by SHA-256 and copied to `public/third-party/beepbox/`.
- **WebPC tweaks** (all in the row's `tweak`, each a failing find/replace): removes the Google Fonts stylesheet (UI falls back to system sans-serif); removes the service-worker registration — upstream registers `scope: "/"` and would precache a third-party CDN (`cdn.jsdelivr.net/lamejs`), shadowing the whole site if it could install — plus `service_worker.js` and macOS `.DS_Store`, and prunes the files WebPC never loads (`beepbox_editor.js`, `beepbox_offline.html`, `index_debug.html`, every `*.map`, and the unused `player/` directory — `index.html` does not link it; the "View in Song Player" menu item, copied HTML embeds and the About-page link to `beepbox_offline.html` now 404 by design); injects `webpc-audio-guard.js` (from `scripts/pc/static-apps/`) into `<head>` before the app's scripts. The tweaked editor JS is syntax-checked with `node:vm` before serving.
- **Audio on close**: closing a WebPC window only hides its iframe, so the guard wraps `AudioContext`/`webkitAudioContext`, records every instance, and exposes `window.webpcAudio = { suspend(), states() }`. It never blocks resume: BeepBox's own Play calls `audioCtx.resume()`. The wrapper defines `window.pcBeforeClose` (desktop.js calls it before hiding): if BeepBox is playing (its `button.pauseButton` is visible only while `synth.playing`) it clicks that own button so the app stops believing it is playing — on reopen the user sees Play and one press plays — then suspends as the guarantee and returns `true`; if the button is missing it suspends only and appends a visible note instead of failing. It suspends on `pagehide` too. Verified headless: Play → `running`; `pcBeforeClose()` → `true`, states → `suspended`, Play button visible; Play → `running`.
- **Work not lost**: the song hash is mirrored to the wrapper-origin `localStorage` key `pc:beepbox:song:v1`. BeepBox updates the hash with `history.replaceState` (no `hashchange` fires), so the wrapper polls the iframe hash every 500 ms and restores the saved hash into a fresh iframe when it differs (the app loads songs via its `hashchange`/`popstate` listeners). Storage failures append a visible warning to the page note; never silent.
- **Storage**: `localStorage` settings keys (`volume`, `colorTheme`, `layout`, `keyboardLayout`, `visibleOctaves`, `exportFormat`, `midiHandlerId`, `selectionCopy`, `instrumentCopy`, …) plus WebPC's `pc:beepbox:song:v1`. No `localStorage.clear`/`indexedDB`/`navigator.storage.getDirectory`. No origin-wide wipe.
- **Network**: zero non-site requests on load and through the play/edit/close flow (verified headless: 58 requests, all `localhost:4322`). Share/shorten menu items (`is.gd`, `tinyurl`, `pastelink`, `vochlea`, `imitone`) and the PayPal donation form only send data when the user explicitly submits them; the song data is in the URL they send — noted on the app page.

## Validation

`node --test tests/pc-static-apps.test.mjs` (table pinning, unsafe-path and fingerprint checks). Headless checks (scratch): `check-sqliteviz.mjs` loads `/pc/apps/sqliteviz/`, waits for the app UI, logs every non-localhost request (none), drives the UI with a 3-row CSV through the drop-zone picker and the CSV import dialog, runs `SELECT count(*) FROM rows` (result 3) and saves `sqliteviz.png`. Note: bare `SELECT count(*)` with no `FROM` returns 1 in SQLite by design; the table must be named explicitly. `check-beepbox.mjs` loads `/pc/apps/beepbox/`, confirms zero non-localhost requests, presses Play (`webpcAudio.states()` → `running`), calls `window.pcBeforeClose()` (returns `true`, states → `suspended`, Play button visible again), plays again (BeepBox's own Play resumes the suspended context → `running`), changes a note (hash changes and the `pc:beepbox:song:v1` mirror matches), reloads and confirms the saved song hash is restored, and saves `beepbox.png`.
