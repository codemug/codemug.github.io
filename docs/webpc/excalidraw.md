# Excalidraw in WebPC

Excalidraw 0.18.1 (MIT) — the hand-drawn diagram editor — integrated as a same-origin iframe under `/pc/apps/excalidraw/`, fully local: no CDN fonts, no share or collaboration backends.

## Prepare and update

Run `node scripts/pc/prepare-excalidraw.mjs` (wire it into `assets:pc` after the other preparers). The package is pinned: `package.json` devDependency `@excalidraw/excalidraw@0.18.1` (installed with `--save-exact --ignore-scripts`) and the npm lockfile integrity, both required to match before a re-prepare is skipped.

The preparer esbuild-bundles `scripts/pc/excalidraw/main.jsx` (with the installed react/react-dom) into `public/pc/vendor/excalidraw/excalidraw.js` (production conditions, minified, ESM), copies the package's prebuilt `dist/prod/index.css` verbatim as `excalidraw.css` and the full `dist/prod/fonts/` tree (the CSS's `./fonts/...` refs resolve against it; the lazy canvas-font files load from the same tree), writes `webpc-config.js` (sets `window.EXCALIDRAW_ASSET_PATH = "/pc/vendor/excalidraw/"` **before** the bundle loads, so no font can resolve to a CDN) and a CSP-locked `index.html`. A `.release.json` marker (version + lockfile integrity + fingerprint of the preparer source, `main.jsx`, `storage.mjs` and the react versions) makes the run idempotent. `public/third-party/excalidraw/` holds the pinned repo `LICENSE` (tag `v0.18.1`, SHA-256; the npm package ships no licence file), `BUNDLED-NOTICES.txt` (full licence texts of every bundled package, via `writeBundleNotices`) and `WEBPC.txt`.

## What WebPC changed

- **Self-hosted fonts**: `EXCALIDRAW_ASSET_PATH` defaults to a CDN upstream; `webpc-config.js` points it at `/pc/vendor/excalidraw/` before the app loads. Fonts (all nine families, including the per-subset hashed `woff2` files) ship under the vendor folder and load lazily from there. The prep step also strips the upstream esm.sh CDN fallback from the bundle's `createUrls()` (a regex that must match exactly once, or the prep throws) and removes the now-dead `ASSETS_FALLBACK_URL` literal, so every canvas-font `src` list is local-only — by construction no font can resolve to a CDN, and `grep -rl 'esm.sh\|unpkg.com\|jsdelivr' public/pc/vendor/excalidraw` returns nothing.
- **CSP**: the vendor `index.html` carries a CSP meta: `script-src 'self'`, `font-src 'self' data: blob:`, `connect-src 'self' blob: data:`, `worker-src 'self' blob:`, `frame-src 'self'`, third-party `img`/`object` sources blocked. `font-src`/`connect-src` allow only `self`/`blob:`/`data:`, so a CDN font can never load even if the code regressed. The config is a separate file (no inline scripts); `style-src 'unsafe-inline'` is kept for React's inline style attributes. One consequence: the `image-blob-reduce` helper in the bundle spawns a `data:`-URL worker, which the CSP blocks — the helper has a built-in fallback (returns false, image import still works, only a blob-size optimisation is skipped). The font-subset worker uses a same-origin chunk URL and is allowed.
- **Local save**: the scene (elements, a whitelisted `appState` view-state subset, files) autosaves debounced (1 s) to the WebPC-namespaced `localStorage` key `pc:excalidraw:scene:v1` and is restored on open. Stored data is validated before restore (wrong version tag, malformed elements/appState/files, oversized scenes and foreign shapes are rejected — a blank canvas opens and the stored copy is left untouched, with a visible note). Storage failures (blocked storage, quota) show as visible status text in the app, never silently. Excalidraw's own "Save to browser" keeps a separate copy under its own key; native Export → Save to disk (`.excalidraw`) and Open from its menu stay available.
- **Close hook**: `window.pcBeforeClose` (called by the desktop before hiding the window) and `pagehide` flush the pending save; the wrapper page (`src/scripts/pc/apps/excalidraw.mjs`) and the app itself both flush, idempotently.
- **Theme**: the app follows the desktop's `pc:theme` message via Excalidraw's `theme` prop (same pattern as the Craft and Docs apps), initial theme from `prefers-color-scheme`.
- **No backends**: no collaboration props are passed (the bundled room/collab client, with its `firebaseio.com` / `cloudfunctions.net` URLs, stays inactive) and no `onExportToBackend`. The Excalidraw library, Excalidraw+ and share links are user-click new-tab links only; in-page third-party embeds and pasted external image/GIF URLs are CSP-blocked (the page is same-origin locked). Noted on the app page.

## Storage (BRIEF rule 6)

No `navigator.storage.getDirectory`, no `localStorage.clear`/`sessionStorage.clear`, no `indexedDB.deleteDatabase`. The only Cache API use is `caches.open("web-share-target")` — its own named cache for the web-share-target PWA feature. `localStorage` keys: Excalidraw's own (its "save to browser" copy, UI prefs, library) plus WebPC's `pc:excalidraw:scene:v1`. **No origin-wide wipe; no scoping needed.**

## Network (BRIEF rule 5)

The bundle contains third-party URL strings (`app.excalidraw.com`, `plus.excalidraw.com`, `json.excalidraw.com`, `libraries.excalidraw.com`, `giphy.com`, `player.vimeo.com`, social widget hosts) — all user-initiated: new-tab links, share-dialog targets or URL-pattern handling, none fetched on load. The collaboration client code is present but inactive (no collaboration props are passed). **Verified by the headless check** (a Playwright script against the dev server, not committed): **zero non-localhost requests** on load and through draw / font-switch / theme / `pcBeforeClose` / reload, and zero failed requests. (The prep-time CDN strip removes the only load-time external fetch the app could make: the esm.sh font fallback.) Note on headless fidelity: in headless Chromium, lazily-loaded canvas fonts read as `unloaded` in `document.fonts` for same-origin `FontFace`s — a headless limitation (a local-only control `FontFace` also issues no fetch in headless, while a cross-origin one does). In a real browser the fonts resolve to the local `woff2` files (served 200) via the browser's native font loader.

## Validation

`node --test tests/pc-excalidraw.test.mjs` — 6 tests for the pure persistence helpers (`scripts/pc/excalidraw/storage.mjs`): key namespacing, appState-subset serialization, round-trip, corrupt/foreign/oversized rejection, and read/write against in-memory storage including blocked-storage and quota errors. A headless check (not committed) opens `/pc/apps/excalidraw/`, waits for ready, draws a rectangle and a text element via the imperative API (`updateScene({ elements, captureUpdate })` — 0.18.1 takes a scene object, not a bare array), switches the text's font family (local font load), confirms the debounced autosave in `localStorage`, reads `appState.theme` before/after a `pc:theme` message, calls `pcBeforeClose()`, reloads and confirms both elements restore (ids, text, font family), and prints a SUMMARY (requests per host, local-font 200 count, non-local count = 0, plus the functional readings). **Status: run — non-local requests 0, failed 0, autosave/theme/`pcBeforeClose`/restore all pass.**
